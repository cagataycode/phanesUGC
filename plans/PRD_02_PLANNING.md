# Phase 2 — Creative Brief, Script Generation & Scene Planning

**Parent Document:** `PRD_00_OVERVIEW.md`  
**Agent Stages:** `context_ready → brief_ready → script_ready → scenes_ready`

---

## 1. Phase Objective

Transform the normalized request and product context into a structured creative brief, generate an ad script optimized for short-form social video, evaluate the script against quality criteria, and plan individual scenes with visual and timing instructions.

All three stages in this phase are LLM-driven — they use Gemini to convert unstructured intent into precise, structured production instructions.

---

## 2. Pipeline Stages in This Phase

```
NormalizedRequest + ProductContext
  → Stage 4: Creative Brief Construction
  → Stage 5: Script Generation
  → Stage 6: Script Evaluation (Quality Gate)
  → Stage 7: Scene Planning
  → Output: CreativeBrief + AdScript + ScenePlan[]
```

---

## 3. Stage 4: Creative Brief Construction

### 3.1 Purpose

Convert the raw user input, product context, and prompt into a clean internal brief that downstream services can consume deterministically.

The brief is the **single source of truth** for all creative decisions. Script generation, scene planning, and asset selection all read from the brief.

### 3.2 Brief Generation Process

1. Collect `NormalizedRequest` and `ProductContext` from previous stages
2. Send to Gemini LLM with a structured prompt
3. Receive structured JSON brief
4. Validate required fields
5. Store brief artifact
6. Transition state to `brief_ready`

### 3.3 Gemini Prompt Template for Brief

```
You are an expert advertising strategist specializing in short-form social video ads.

Given the following inputs, create a structured creative brief for a {duration_sec}-second {platform} ad.

User prompt: {prompt}
Product name: {product_name}
Product description: {description}
Product benefits: {benefits}
Pain points: {pain_points}
Target audience: {target_audience or "infer from product context"}
Tone: {tone}
Language: {language}
CTA: {cta or "suggest an appropriate CTA"}

Requirements:
- The brief must be specific enough to produce a coherent ad script
- Infer any missing fields from context
- The visual style should match the tone and platform
- The ad must fit within {duration_sec} seconds when spoken aloud

Respond with a JSON object matching this exact schema:
{schema}
```

**Gemini Model:** `gemini-2.5-flash`

### 3.5 Field Inference Rules

| Field | If Missing | Agent Behavior |
|---|---|---|
| `target_audience` | Not provided by user | LLM infers from product context and prompt |
| `cta` | Not provided by user | LLM generates a suitable CTA |
| `pain_points` | Not in product context | LLM infers from product benefits (inverse) |
| `proof_points` | No reviews or data available | LLM omits or generates generic social proof |
| `key_message` | Never user-provided | Always generated by LLM |
| `offer` | Not provided | LLM derives from product description |

## 4. Stage 5: Script Generation

### 4.1 Purpose

Generate a short-form ad script optimized for the target platform, with scene-by-scene narration, a strong hook, clear body, and explicit CTA.

### 4.2 Script Generation Process

1. Read `CreativeBrief` artifact
2. Send to Gemini LLM with script generation prompt
3. Receive structured script JSON
4. Validate script structure
5. Run script through evaluation gate (Stage 6)
6. Store script artifact
7. Transition state to `script_ready`

### 4.3 Gemini Prompt Template for Script

```
You are an expert short-form ad copywriter specializing in {platform} ads.

Using the following creative brief, write a {duration_sec}-second video ad script.

Creative Brief:
{brief_json}

Script requirements:
- Start with a strong hook that grabs attention in the first 2-3 seconds
- The hook should address a pain point or create curiosity
- Body should communicate 2-3 key benefits clearly
- End with a clear, direct call-to-action
- Split the script into {scene_count} scenes
- Each scene narration should be 1-2 sentences
- Sentences must be short enough for readable subtitles (max 10 words per subtitle line)
- Total spoken words should fit in {duration_sec} seconds at ~150 words per minute
- Language: {language}
- Tone: {tone}
- Script style: {script_style}

Respond with a JSON object matching this exact schema:
{schema}
```

### 4.4 Scene Count Calculation

| Duration | Recommended Scenes |
|---|---|
| 15 seconds | 3 scenes |
| 30 seconds | 4-5 scenes |
| 45 seconds | 5-6 scenes |
| 60 seconds | 6-8 scenes |

## 5. Stage 6: Script Evaluation (Quality Gate)

### 5.1 Purpose

Evaluate the generated script against quality criteria before proceeding to scene planning. This is the first quality gate in the pipeline.

### 5.2 Evaluation Checks

| Check | Rule | Outcome |
|---|---|---|
| **Hook presence** | Scene 1 must have `purpose: "hook"` | Fail → regenerate script |
| **CTA presence** | Last scene must have `purpose: "cta"` | Fail → regenerate script |
| **Duration fit** | `estimated_duration_sec` within ±20% of `duration_sec` | Fail → regenerate with adjusted word count |
| **Word count** | Total words ≤ `duration_sec × 2.5` (150 wpm) | Warn → may regenerate |
| **Scene count** | Matches recommended range for duration | Warn → acceptable |
| **Subtitle readability** | No narration line exceeds 20 words | Fail → regenerate with shorter sentences |
| **Language match** | Script language matches requested language | Fail → regenerate |
| **CTA clarity** | CTA text is explicit and actionable | Warn → acceptable |

### 5.3 Evaluation Process

1. Run rule-based checks (duration, word count, scene count, structure)
2. Optionally run LLM evaluation for subjective quality (hook strength, persuasiveness)
3. If critical check fails: regenerate script (max 2 retries)
4. If all pass: proceed to scene planning
5. Store evaluation result

### 5.4 LLM Quality Evaluation (Optional)

```
Rate this ad script on a scale of 1-10 for:
1. Hook strength (does it grab attention immediately?)
2. Clarity (is the message easy to understand?)
3. Persuasiveness (does it make you want to act?)
4. CTA effectiveness (is the call-to-action clear and compelling?)

Script:
{script_json}

Respond with scores and brief feedback for each criterion.
If any score is below 5, suggest a specific improvement.
```

### 5.5 Retry Behavior

| Failure Type | Retry Action |
|---|---|
| Duration too long | Regenerate with explicit "make it shorter" instruction |
| Duration too short | Regenerate with "add more detail" instruction |
| Missing hook | Regenerate with "start with a stronger hook" instruction |
| Missing CTA | Regenerate with "end with a clear CTA" instruction |
| Subtitle unfriendly | Regenerate with "use shorter sentences" instruction |
| Max retries reached | Accept best attempt, log quality warning |

## 6. Stage 7: Scene Planning

### 6.1 Purpose

Convert the approved script into detailed scene-level production instructions. Each scene becomes a self-contained unit with visual direction, timing, motion, and overlay specifications.

### 6.2 Scene Planning Process

1. Read `AdScript` artifact
2. Send to Gemini LLM with scene planning prompt
3. Receive structured scene plan JSON
4. Validate each scene has required fields
5. Store scene plan artifact
6. Transition state to `scenes_ready`

### 6.3 Gemini Prompt Template for Scene Planning

```
You are a video production director specializing in short-form social ads.

Given this ad script, create detailed scene-by-scene production instructions for a {aspect_ratio} {platform} video.

Script:
{script_json}

Product context:
- Product name: {product_name}
- Available product images: {image_urls}
- Available brand assets: {brand_asset_keys}

For each scene, specify:
1. Visual type: what kind of visual (product_shot, lifestyle, text_animation, screen_recording, abstract)
2. Visual prompt: detailed description for image/video generation or stock search
3. Camera motion: how the camera should move (static, slow_push_in, slow_pull_out, pan_left, pan_right, none)
4. Overlay text: text to display on screen
5. Overlay position: where text appears (top, center, bottom)
6. Transition in: how the scene starts (cut, fade, slide_left, slide_right, zoom)
7. Transition out: how the scene ends
8. Whether to use a product image from available assets or generate/find a visual

Respond with a JSON array matching this exact schema:
{schema}
```

### 6.5 Visual Type Definitions

| Type | Description | Typical Source |
|---|---|---|
| `product_shot` | Product UI, packaging, or hero image | Uploaded assets, scraped images |
| `lifestyle` | People using the product or in relevant context | Stock media, generated images |
| `text_animation` | Animated text or kinetic typography | Generated via renderer |
| `screen_recording` | Product demo or walkthrough | Uploaded assets |
| `abstract` | Gradient, particles, or abstract motion | Generated |
| `testimonial` | Review text or social proof overlay | Generated from reviews |

### 6.6 Scene Duration Distribution

The LLM distributes duration across scenes, but must follow these constraints:

| Constraint | Rule |
|---|---|
| Sum of scene durations | Must equal target `duration_sec` ±1 second |
| Hook scene | 3-5 seconds max |
| CTA scene | 5-10 seconds (longest for retention) |
| Body scenes | Remaining time distributed evenly |
| Minimum scene | 3 seconds (anything shorter is disorienting) |

## 7. Adapter Interfaces

### 7.1 LLMAdapter (for planning)

```typescript
interface LLMAdapter {
  generateBrief(request: NormalizedRequest, context: ProductContext): Promise<CreativeBrief>;
  generateScript(brief: CreativeBrief): Promise<AdScript>;
  evaluateScript(script: AdScript, brief: CreativeBrief): Promise<ScriptEvaluation>;
  planScenes(script: AdScript, brief: CreativeBrief, availableAssets: AssetReference[]): Promise<ScenePlan[]>;
}

interface ScriptEvaluation {
  passed: boolean;
  scores: {
    hookStrength: number;
    clarity: number;
    persuasiveness: number;
    ctaEffectiveness: number;
  };
  issues: string[];
  suggestions: string[];
}
```

## 8. Quality Gate: Script & Scene Readiness

Before transitioning to Phase 3, the agent verifies:

| Check | Required |
|---|---|
| Brief has all required fields | Yes |
| Script has hook, body, and CTA | Yes |
| Script duration estimate is within tolerance | Yes |
| Each scene has visual type and prompt | Yes |
| Scene durations sum to target duration | Yes |
| Each scene has overlay text | No (some scenes may have none) |
| Each scene has transition instructions | Yes (defaults applied if missing) |
