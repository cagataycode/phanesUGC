# Phase 1 — Input Collection & Product Context Acquisition

**Parent Document:** `PRD_00_OVERVIEW.md`  
**Agent Stages:** `platform_ready → normalized → context_ready`

---

## 1. Phase Objective

Accept user input, validate and normalize it, optionally scrape product URLs, extract structured product data using AI, and produce a complete normalized request ready for the planning phase.

This phase assumes Stage 0.5 platform setup is already in place so every request is associated with an authenticated user and an owning account/workspace.

---

## 2. Pipeline Stages in This Phase

```
User Request
  → Stage 1: Request Intake
  → Stage 2: Validation & Normalization
  → Stage 3: Product Context Acquisition (URL Scraping + AI Extraction)
  → Output: NormalizedRequest + ProductContext
```

---

## 3. Stage 1: Request Intake

### 3.0 Platform Preconditions

Before request intake begins, the platform layer must already provide:

- authenticated identity via Firebase Auth
- resolved owning `user_id`
- resolved owning `account_id` / workspace id
- active subscription or usage entitlement context
- storage access policy for uploaded assets

### 3.1 Required Inputs

| Field          | Type    | Description                                             |
| -------------- | ------- | ------------------------------------------------------- |
| `prompt`       | string  | Free-text description of the desired ad                 |
| `platform`     | enum    | `tiktok`, `instagram_reels`, `youtube_shorts`           |
| `aspect_ratio` | enum    | `9:16`, `1:1`                                           |
| `duration_sec` | integer | Target ad duration: `15`, `30`, `45`, `60`              |
| `language`     | string  | Language code: `en`, `de`, `es`, `fr`, `tr`, `it`, `pt` |

### 3.2 Optional Inputs

| Field                 | Type     | Description                                                 |
| --------------------- | -------- | ----------------------------------------------------------- |
| `link_id`             | uuid     | Reference to a previously created product link              |
| `tone`                | string   | Ad tone: `direct`, `professional`, `casual`, `enthusiastic` |
| `target_audience`     | string   | Description of target audience                              |
| `cta`                 | string   | Call-to-action text                                         |
| `visual_style`        | string   | `dynamic`, `minimalist`, `bold`, `cinematic`                |
| `script_style`        | string   | `professional`, `casual`, `enthusiastic`, `direct`          |
| `subtitle_style`      | enum     | `standard`, `kinetic`                                               |
| `no_background_music` | boolean  | Disable background music                                    |
| `no_caption`          | boolean  | Disable subtitles                                           |
| `no_cta`              | boolean  | Disable CTA overlay                                         |
| `product_info`        | object   | Manual product information (see below)                      |
| `product_urls`        | string[] | URLs to scrape (alternative to link_id)                     |
| `brand_assets`        | string[] | Uploaded asset references                                   |
| `webhook_url`         | string   | URL for completion notification                             |

### 3.3 Manual Product Info Schema

```json
{
  "name": "ProductX",
  "description": "AI-powered ad creation tool",
  "benefits": ["save time", "auto subtitles", "social-ready"],
  "pricing": "$29/mo",
  "offer": "Free trial for 14 days"
}
```

## 4. Stage 2: Validation & Normalization

### 4.1 Validation Rules

| Rule                                 | Behavior                                  |
| ------------------------------------ | ----------------------------------------- |
| `prompt` is empty or missing         | Reject with 400 error                     |
| `platform` is invalid                | Reject with 400 error                     |
| `aspect_ratio` is invalid            | Reject with 400 error                     |
| `duration_sec` is not in allowed set | Reject with 400 error                     |
| `language` is not supported          | Reject with 400 error                     |
| `tone` is missing                    | Default to `direct`                       |
| `target_audience` is missing         | Will be inferred by LLM in planning phase |
| `cta` is missing                     | Will be generated by LLM in script phase  |
| `visual_style` is missing            | Default to `dynamic`                      |
| `script_style` is missing            | Default to `professional`                 |
| `subtitle_style` is missing          | Default to `kinetic`                      |

### 4.2 Normalization Process

The normalizer must:

1. Strip and trim all string inputs
2. Apply defaults for missing optional fields
3. Validate `link_id` exists if provided
4. Merge `product_info` fields with link-extracted data (user-provided takes precedence)
5. Store the original raw input as `raw_inputs_json`
6. Store the processed input as `normalized_inputs_json`
7. Attach request ownership metadata (`user_id`, `account_id`, `subscription_tier`)
8. Transition job state to `normalized`

## 5. Stage 3: Product Context Acquisition

### 5.1 Two-Step Context Flow

Product context can be acquired in two ways:

#### Path A: Pre-created Link (Recommended)

```
1. User calls POST /api/v1/links with URL
2. System scrapes, extracts, returns structured data
3. User reviews and optionally edits via PUT /api/v1/links/{id}
4. User submits ad job with link_id reference
5. Agent uses the pre-extracted and user-reviewed data
```

#### Path B: Inline URL Scraping

```
1. User provides product_urls in the ad creation request
2. Agent scrapes URLs during context acquisition stage
3. No user review step — agent uses raw extraction
```

Path A is preferred because it allows the user to review and correct extracted data before generation, reducing wasted credits.

### 5.2 Scraping Process

When a URL needs to be scraped:

1. Fetch the page HTML
2. Parse the DOM for structured product data
3. Extract candidate media (images, videos)
4. Send extracted raw content to Gemini LLM for intelligent summarization

### 5.3 Extraction Targets

| Target                | Description                        | Source                              |
| --------------------- | ---------------------------------- | ----------------------------------- |
| `product_name`        | Product or brand name              | Meta tags, headings, OG tags        |
| `description`         | Product description                | Meta description, main content      |
| `benefits`            | Key product benefits               | Content analysis via LLM            |
| `pricing`             | Price if visible                   | Structured data, price elements     |
| `offer`               | Special offers or promotions       | Content analysis via LLM            |
| `cta`                 | Call-to-action from page           | Button text, form labels            |
| `reviews`             | Customer review excerpts           | Review sections, testimonial blocks |
| `image_urls`          | Product and lifestyle images       | img tags, OG images, gallery        |
| `video_urls`          | Product videos if available        | video tags, embedded players        |
| `brand_colors`        | Primary brand colors if detectable | CSS analysis                        |
| `ai_summary`          | AI-generated product summary       | Gemini LLM                          |
| `ai_target_audiences` | AI-inferred target audiences       | Gemini LLM                          |

### 5.4 AI Extraction via Gemini

After raw HTML extraction, send the extracted text content to Gemini for intelligent processing:

**Gemini Prompt Template:**

```
You are a product analyst. Given the following webpage content, extract:
1. A concise product summary (2-3 sentences)
2. The top 3-5 target audiences for this product
3. Key benefits that would work in a short-form ad
4. Pain points the product solves
5. The strongest call-to-action angle

Webpage content:
{extracted_text}

Respond in JSON format.
```

**Gemini Model:** `gemini-2.5-flash` (fast, cost-effective for extraction)

### 5.6 Context Merging Rules

When both manual `product_info` and scraped data exist:

| Field                 | Priority                                            |
| --------------------- | --------------------------------------------------- |
| `product_name`        | User-provided > Scraped                             |
| `description`         | User-provided > Scraped                             |
| `benefits`            | Merge (user-provided first, then scraped additions) |
| `pricing`             | User-provided > Scraped                             |
| `cta`                 | User-provided > Scraped                             |
| `image_urls`          | Merge (user uploads first, then scraped)            |
| `ai_summary`          | Always from LLM                                     |
| `ai_target_audiences` | Always from LLM                                     |
| `reviews`             | Scraped only (user doesn't provide these)           |

### 5.7 Fallback Behavior

| Failure                         | Behavior                                                         |
| ------------------------------- | ---------------------------------------------------------------- |
| URL is unreachable              | Continue with manual product_info; mark scrape as failed         |
| Page is JavaScript-rendered SPA | Attempt headless rendering; if fails, continue with manual input |
| No product data extractable     | Continue with prompt and manual product_info only                |
| Gemini extraction fails         | Use raw extraction without AI enrichment                         |
| No product context at all       | Agent proceeds — LLM will work from prompt alone                 |

### 5.8 State Transition

After context acquisition completes:

- Store `ProductContext` artifact
- Transition job state to `context_ready`
- If scraping was attempted, record scrape status (success/partial/failed)

## 6. Adapter Interfaces

### 6.1 ScraperAdapter

```typescript
interface ScraperAdapter {
  scrape(url: string): Promise<RawScrapedContent>;
}

interface RawScrapedContent {
  url: string;
  title: string;
  description: string;
  bodyText: string;
  imageUrls: string[];
  videoUrls: string[];
  structuredData: Record<string, unknown> | null;
  statusCode: number;
}
```

### 6.2 LLMAdapter (for extraction)

```typescript
interface LLMAdapter {
  extractProductContext(
    rawContent: RawScrapedContent,
  ): Promise<AIExtractedContext>;
}

interface AIExtractedContext {
  aiSummary: string;
  aiTargetAudiences: string[];
  benefits: string[];
  painPoints: string[];
  ctaAngle: string;
}
```

## 7. API Endpoints for This Phase

All endpoints in this phase require authenticated access and are scoped to the owning account/workspace.

### Create Product Link

```http
POST /api/v1/links
```

Scrapes a URL and returns structured extraction. User can review before generating.

### Update Product Link

```http
PUT /api/v1/links/{id}
```

User edits extracted data (override product name, description, images, etc.).

### Get Product Link

```http
GET /api/v1/links/{id}
```

Returns the current state of the extracted product data.

## 8. Quality Gate: Input Completeness

Before transitioning to Phase 2, the agent checks:

| Check                                                          | Behavior                                         |
| -------------------------------------------------------------- | ------------------------------------------------ |
| Prompt is present and non-trivial                              | Required — fail job if missing                   |
| Platform, aspect ratio, duration, language are set             | Required — should be guaranteed by normalization |
| Some product context exists (manual OR scraped OR prompt-only) | Pass — agent can work from prompt alone          |
| At least one image available for scene assets                  | Optional — stock/generated fallback available    |

This is a soft gate — the agent can proceed with minimal context but records what's missing for downstream stages to handle.
