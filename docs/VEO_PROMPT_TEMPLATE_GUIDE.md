## Part 1: Veo Scene Prompt Template (Annotated)

This is the canonical JSON structure that gets built for **each scene** before being sent to the Veo API. Every field is annotated with its purpose.

```jsonc
{
  // ─── SCENE IDENTITY ───
  // These fields track which scene this is within the project.
  // They are NOT sent to Veo — they are used by the pipeline for ordering,
  // storage, and Firestore persistence.

  "scene_id": 1,
  // PURPOSE: 1-based scene sequence number. Maps to sceneOrder in Firestore.
  // Used to order scenes in the final timeline and to match with
  // script.voiceoverLines[].scene for subtitle alignment.

  "project_id": "proj_abc123",
  // PURPOSE: Parent project reference. Used for GCS path construction
  // and Firestore document lookup. Not sent to Veo.

  // ─── TECHNICAL CONSTRAINTS ───
  // These define the video output format. Derived from the user's
  // ad creation form inputs (platform, aspect_ratio, duration).

  "duration_seconds": 5,
  // PURPOSE: How long this scene's video clip should be.
  // Veo uses this to control generation length.
  // The sum of all scene durations should equal the total ad duration.
  // Typical ranges: 3-8s per scene for a 15-30s ad.
  // SOURCE: Calculated by the scene planner based on script pacing.

  "aspect_ratio": "9:16",
  // PURPOSE: Frame dimensions for the generated video.
  // "9:16" = vertical (TikTok, Reels, Shorts) — primary for MVP.
  // "1:1" = square (optional).
  // SOURCE: Directly from user's ad creation form.

  // ─── THE PROMPT ───
  // This is the core creative instruction sent to Veo.
  // It is a structured object that gets serialized into Veo's prompt format.

  "prompt": {

    // ── INTENT ──
    "intent": "Create a close-up product showcase video of a sleek wireless earbud case being opened on a marble surface, revealing the earbuds inside with soft studio lighting.",
    // PURPOSE: The primary creative direction for the entire scene.
    // This is the most important field — it tells Veo WHAT to generate.
    // Should be 1-3 sentences. Specific and visual. Avoid abstract concepts.
    // SOURCE: Generated by Gemini from the script line + product context.
    // TIPS:
    //   - Lead with the visual action ("A hand reaches for...", "Close-up of...")
    //   - Include the product naturally
    //   - Describe the setting/environment
    //   - Mention lighting mood

    // ── SHOT DESCRIPTION ──
    "shot": {
      "type": "product_showcase",
      // PURPOSE: Categorizes the shot for internal tracking and potential
      // style-specific rendering adjustments.
      // VALUES: "product_showcase" | "lifestyle" | "testimonial_style" |
      //         "text_overlay_scene" | "before_after" | "unboxing" |
      //         "demo" | "social_proof" | "cta_scene" | "hook"
      // SOURCE: Gemini decides based on the script line's role in the ad.

      "framing": "close-up centered on the product with shallow depth of field",
      // PURPOSE: Tells Veo how tight or wide the frame should be.
      // This controls composition — what's visible and what's not.
      // EXAMPLES: "extreme close-up on texture", "medium shot waist-up",
      //           "wide establishing shot", "over-the-shoulder"
      // SOURCE: Gemini decides based on shot type and ad pacing.

      "camera_angle": "slightly elevated looking down at 30 degrees",
      // PURPOSE: The virtual camera's position relative to the subject.
      // Controls perspective and visual weight.
      // EXAMPLES: "eye level", "low angle looking up", "top-down bird's eye",
      //           "dutch angle", "front-facing selfie angle"
      // SOURCE: Gemini decides. Eye-level is safest default.

      "camera_motion": "slow_push_in",
      // PURPOSE: How the virtual camera moves during the clip.
      // Adds dynamism. Must match the scene's energy level.
      // VALUES: "static" | "slow_push_in" | "slow_pull_out" | "pan_left" |
      //         "pan_right" | "tilt_up" | "tilt_down" | "orbit" |
      //         "handheld" | "tracking" | "crane_up" | "crane_down"
      // SOURCE: Gemini decides. "static" or "slow_push_in" are safest.
      // NOTE: Maps to scene.cameraMotion in Firestore schema.

      "lens_feel": "35mm cinematic lens with natural bokeh",
      // PURPOSE: Simulates a specific lens look. Controls depth of field,
      // distortion, and overall aesthetic.
      // EXAMPLES: "smartphone front camera", "wide angle action cam",
      //           "macro lens extreme close-up", "anamorphic cinematic"
      // SOURCE: Gemini decides based on visual_style preference.
      // For "minimalist" style -> clean 50mm. For "cinematic" -> 35mm anamorphic.
      // For "dynamic" -> wider lens with more movement.

      "composition": "product centered in frame, negative space on top third for potential text overlay"
      // PURPOSE: Guides spatial arrangement within the frame.
      // Important for scenes that will have text overlays or subtitles.
      // Should leave safe areas clear (top 120px, bottom 180px for social UI).
      // SOURCE: Gemini decides. Should always consider subtitle placement.
    },

    // ── SUBJECT ──
    "subject": {
      "type": "product",
      // PURPOSE: What the primary subject of the scene is.
      // VALUES: "product" | "person" | "person_with_product" | "environment" |
      //         "text_only" | "abstract"
      // SOURCE: Gemini decides based on scene type and script.

      "description": "a pair of matte black wireless earbuds in a compact white charging case",
      // PURPOSE: Detailed visual description of the subject.
      // For products: describe appearance, color, material, size, shape.
      // For people: describe appearance, clothing, pose, expression.
      // SOURCE: Built from product context (name, description, scraped data).
      // CRITICAL: Be specific and visual. "earbuds" is too vague.
      //           "matte black wireless earbuds with silver accents" is good.

      "action": "the case lid opens smoothly, revealing the earbuds nestled inside with a soft LED indicator light pulsing once",
      // PURPOSE: What the subject DOES during the scene.
      // This is the motion/animation instruction for Veo.
      // Should describe a clear, simple action sequence.
      // SOURCE: Gemini generates based on script context and shot type.
      // TIPS:
      //   - Keep actions simple — Veo handles 1-2 actions well per scene
      //   - "A hand picks up the product" > "someone grabs it excitedly"
      //   - Physical, observable actions > emotional descriptions

      "identity_notes": null
      // PURPOSE: Used ONLY for person subjects where visual consistency
      // matters across scenes (same person appearing in multiple scenes).
      // Contains appearance anchors: skin tone, hair, clothing, etc.
      // For product scenes, this is null.
      // SOURCE: Gemini builds from script if a recurring character exists.
    },

    // ── ENVIRONMENT ──
    "environment": {
      "location": "modern minimalist studio tabletop",
      // PURPOSE: The setting/background for the scene.
      // Should be specific enough for Veo to render consistently.
      // EXAMPLES: "cozy bedroom with warm lighting", "busy city street at dusk",
      //           "clean white studio backdrop", "outdoor cafe terrace"
      // SOURCE: Gemini decides based on product context and visual_style.

      "props": ["marble surface", "soft fabric in background"],
      // PURPOSE: Additional objects in the scene that support the composition.
      // Adds realism and context. Keep to 2-3 items max.
      // SOURCE: Gemini generates. Should complement, not distract from subject.

      "atmosphere": "clean, premium, aspirational",
      // PURPOSE: The emotional quality of the environment.
      // Guides Veo's rendering of color grading, lighting mood, and detail level.
      // EXAMPLES: "warm and inviting", "energetic and vibrant",
      //           "calm and professional", "raw and authentic"
      // SOURCE: Derived from the tone preference (direct/professional/casual/enthusiastic).
      // MAPPING:
      //   direct -> "clean, focused, modern"
      //   professional -> "polished, refined, trustworthy"
      //   casual -> "warm, relaxed, approachable"
      //   enthusiastic -> "vibrant, energetic, exciting"

      "time_of_day": null
      // PURPOSE: If the scene is outdoors, controls natural lighting.
      // VALUES: "golden_hour" | "midday" | "blue_hour" | "night" | null
      // null = indoor/studio (no natural time-of-day lighting).
      // SOURCE: Gemini decides. Most product scenes are null (indoor).
    },

    // ── LIGHTING ──
    "lighting": {
      "style": "soft studio key light from upper left with subtle fill from right",
      // PURPOSE: Primary lighting setup description.
      // This has massive impact on the visual quality and mood.
      // Veo uses this to simulate realistic light behavior.
      // EXAMPLES:
      //   "soft natural window light from camera left"
      //   "dramatic single-source side lighting with deep shadows"
      //   "bright even overhead lighting, no harsh shadows"
      //   "warm golden hour backlight with lens flare"
      // SOURCE: Gemini decides based on visual_style and atmosphere.

      "color_temperature": "neutral white, approximately 5500K",
      // PURPOSE: Controls the warmth/coolness of the light.
      // Warm (3000K) = cozy, intimate. Neutral (5500K) = clean, modern.
      // Cool (7000K) = clinical, tech-forward.
      // SOURCE: Gemini decides. Can also be influenced by brand colors.

      "practical_lights": null
      // PURPOSE: Visible light sources within the scene (lamps, screens, LEDs).
      // Adds realism for interior scenes.
      // EXAMPLES: "laptop screen glow on face", "neon sign in background"
      // null = no visible light sources needed.
      // SOURCE: Gemini decides based on environment.
    },

    // ── AUDIO DIRECTION ──
    "audio": {
      "speech_text": "These earbuds changed everything for me.",
      // PURPOSE: The narration/voiceover text that Veo should generate
      // as embedded speech in the video.
      // This is the script line for this scene.
      // SOURCE: Directly from script.voiceoverLines[scene_id].text
      // CRITICAL: This is what gets spoken in the video. It must match
      //           the script exactly. The subtitle pipeline downstream
      //           will transcribe this audio and align it back to this text.

      "speech_style": "conversational, warm, mid-paced female voice",
      // PURPOSE: Guides the vocal quality and delivery of the speech.
      // Veo uses this to select/generate the appropriate voice.
      // SHOULD INCLUDE: pace, tone, gender, energy level.
      // EXAMPLES:
      //   "energetic male voice, fast-paced, enthusiastic"
      //   "calm authoritative female voice, measured pace"
      //   "casual young male voice, like talking to a friend"
      // SOURCE: Gemini decides based on tone preference and target_audience.
      // MAPPING:
      //   direct + professional -> "clear, confident, measured pace"
      //   casual -> "relaxed, conversational, natural pace"
      //   enthusiastic -> "energetic, upbeat, slightly faster pace"

      "ambient_sound": "subtle studio room tone",
      // PURPOSE: Background audio atmosphere.
      // Adds realism. Should never overpower speech.
      // EXAMPLES: "cafe background chatter", "outdoor birds and wind",
      //           "quiet office hum", null (for pure voiceover)
      // SOURCE: Gemini decides based on environment.

      "music_suggestion": null
      // PURPOSE: NOT sent to Veo. This is a hint for the Remotion
      // composition stage to layer background music.
      // Veo generates speech + ambient only.
      // VALUES: "upbeat lo-fi" | "corporate motivational" | "none" | null
      // SOURCE: Gemini can suggest, but this is handled downstream.
    },

    // ── STYLE DIRECTIVES ──
    "style": {
      "visual_style": "cinematic",
      // PURPOSE: The overall visual rendering approach.
      // This is one of the user's input preferences from the ad creation form.
      // VALUES: "dynamic" | "minimalist" | "bold" | "cinematic"
      // Each maps to different prompt modifiers:
      //   dynamic -> fast cuts, motion, energy, handheld feel
      //   minimalist -> clean lines, negative space, simple compositions
      //   bold -> high contrast, saturated colors, graphic elements
      //   cinematic -> filmic color grading, shallow DOF, dramatic lighting
      // SOURCE: Directly from user's style preference.

      "color_palette": "neutral tones with matte black and white accents",
      // PURPOSE: Guides the dominant colors in the scene.
      // Can be derived from brand colors if available.
      // EXAMPLES: "warm earth tones", "vibrant primary colors",
      //           "monochrome with one accent color", "pastel soft tones"
      // SOURCE: Gemini decides. If brand colors are available from the
      //         product/business data, incorporate them here.

      "rendering_quality": "photorealistic, high detail, 4K texture quality",
      // PURPOSE: Quality floor instruction for Veo.
      // Always set to photorealistic for ad content.
      // SOURCE: Hardcoded. Always "photorealistic" for MVP.

      "aesthetic_reference": "Apple product launch video aesthetic"
      // PURPOSE: A cultural/brand reference that anchors the visual style.
      // Helps Veo understand the target quality level and feel.
      // EXAMPLES: "Nike commercial energy", "Glossier soft product photography",
      //           "tech startup explainer video", "Instagram influencer content"
      // SOURCE: Gemini decides based on product category and target audience.
    },

    // ── TEXT OVERLAYS ──
    "text_overlay": {
      "enabled": true,
      // PURPOSE: Whether this scene has on-screen text (beyond subtitles).
      // Text overlays are rendered by Remotion, NOT burned by Veo.
      // This flag tells the pipeline to include overlay data in the timeline.
      // SOURCE: Gemini decides based on scene type. Hook and CTA scenes
      //         typically have overlays. Body scenes may or may not.

      "text": "Sound That Moves With You",
      // PURPOSE: The on-screen copy. Short, punchy, complementary to speech.
      // NOT the same as the subtitle — this is a design element.
      // SOURCE: Gemini generates based on script context.

      "position": "top_third",
      // PURPOSE: Where on screen the text appears.
      // VALUES: "top_third" | "center" | "bottom_third" | "lower_left"
      // Must not conflict with subtitle safe area (bottom 180px).
      // SOURCE: Gemini decides. "top_third" is safest default.

      "style_hint": "large bold sans-serif, white with drop shadow"
      // PURPOSE: Visual treatment suggestion for Remotion rendering.
      // The actual font/color is applied by the Remotion component,
      // but this guides the creative direction.
      // SOURCE: Gemini decides based on visual_style.
    },

    // ── CTA (Call-to-Action) ──
    "cta": {
      "enabled": false,
      // PURPOSE: Whether this scene is the CTA scene (typically the last scene).
      // Only ONE scene per ad should have cta.enabled = true.
      // SOURCE: Gemini sets true only for the final scene.

      "text": null,
      // PURPOSE: The CTA copy. "Shop Now", "Get Started", "Learn More", etc.
      // SOURCE: From user's cta input field, or Gemini generates if not provided.

      "url_hint": null
      // PURPOSE: Not rendered in video. Stored for potential future use
      // (click-through URLs on social platforms).
      // SOURCE: From product URLs if available.
    }
  },

  // ─── TRANSITIONS ───
  // How this scene connects to adjacent scenes in the timeline.
  // Used by Remotion during final composition, NOT by Veo.

  "transition_in": "cut",
  // PURPOSE: How this scene enters from the previous scene.
  // VALUES: "cut" | "fade" | "slide" | "dissolve"
  // SOURCE: Gemini decides. First scene is always "cut" (no transition in).
  // NOTE: Maps to scene.transitionIn in Firestore schema.

  "transition_out": "fade",
  // PURPOSE: How this scene exits to the next scene.
  // VALUES: "cut" | "fade" | "slide" | "dissolve"
  // SOURCE: Gemini decides. Last scene typically "fade" to black.
  // NOTE: Maps to scene.transitionOut in Firestore schema.

  // ─── NEGATIVE CONSTRAINTS ───
  // Things Veo should explicitly AVOID in generation.

  "negative_prompt": "no text burned into video, no watermark, no logo, no split screen, no collage, no anime, no cartoon, no low resolution, no blurry, no distorted faces, no extra limbs, no unnatural skin",
  // PURPOSE: Tells Veo what NOT to generate. Critical for quality control.
  // Always include the base set above. Gemini can add scene-specific exclusions.
  // IMPORTANT: "no text burned into video" is always included because
  //            text overlays and subtitles are handled by Remotion, not Veo.
  // SOURCE: Base set is hardcoded. Gemini appends scene-specific items.

  // ─── GENERATION METADATA ───
  // Internal tracking fields. Not sent to Veo.

  "generation_config": {
    "model": "veo-3.1",
    // PURPOSE: Which Veo model version to use.
    // SOURCE: Hardcoded for MVP. May become configurable later.

    "seed": null,
    // PURPOSE: Optional reproducibility seed.
    // If set, the same prompt + seed produces similar output.
    // Useful for regeneration with minor prompt tweaks.
    // SOURCE: null for first generation. Stored after generation for re-use.

    "safety_filter": "standard",
    // PURPOSE: Veo content safety filtering level.
    // VALUES: "strict" | "standard" | "relaxed"
    // SOURCE: Hardcoded to "standard" for MVP.

    "retry_count": 0,
    // PURPOSE: How many times this scene has been regenerated.
    // Incremented on each retry. Used for monitoring.

    "priority": "normal"
    // PURPOSE: Queue priority for the generation job.
    // VALUES: "normal" | "high"
    // "high" could be used for paid users in the future.
    // SOURCE: Hardcoded to "normal" for MVP.
  }
}
```

## Part 2: Veo API Prompt Serialization

The structured JSON above is **not sent directly to Veo as JSON**. It gets serialized into a natural language prompt string that Veo consumes. Here is how to convert the template into the actual Veo API call:

### 2.1 Prompt Assembly Function

```typescript
// src/services/veo-prompt-builder.service.ts

interface VeoScenePrompt {
  scene_id: number;
  project_id: string;
  duration_seconds: number;
  aspect_ratio: string;
  prompt: {
    intent: string;
    shot: {
      type: string;
      framing: string;
      camera_angle: string;
      camera_motion: string;
      lens_feel: string;
      composition: string;
    };
    subject: {
      type: string;
      description: string;
      action: string;
      identity_notes: string | null;
    };
    environment: {
      location: string;
      props: string[];
      atmosphere: string;
      time_of_day: string | null;
    };
    lighting: {
      style: string;
      color_temperature: string;
      practical_lights: string | null;
    };
    audio: {
      speech_text: string;
      speech_style: string;
      ambient_sound: string | null;
      music_suggestion: string | null;
    };
    style: {
      visual_style: string;
      color_palette: string;
      rendering_quality: string;
      aesthetic_reference: string;
    };
    text_overlay: {
      enabled: boolean;
      text: string | null;
      position: string | null;
      style_hint: string | null;
    };
    cta: {
      enabled: boolean;
      text: string | null;
      url_hint: string | null;
    };
  };
  transition_in: string;
  transition_out: string;
  negative_prompt: string;
  generation_config: {
    model: string;
    seed: number | null;
    safety_filter: string;
    retry_count: number;
    priority: string;
  };
}

function buildVeoPromptString(scene: VeoScenePrompt): string {
  const p = scene.prompt;
  const parts: string[] = [];

  // Core visual intent
  parts.push(p.intent);

  // Shot details
  parts.push(`${p.shot.framing}.`);
  parts.push(`Camera angle: ${p.shot.camera_angle}.`);
  if (p.shot.camera_motion !== 'static') {
    parts.push(`Camera motion: ${p.shot.camera_motion.replace(/_/g, ' ')}.`);
  }
  parts.push(`${p.shot.lens_feel}.`);

  // Subject action
  if (p.subject.action) {
    parts.push(p.subject.action);
  }

  // Identity persistence (for person subjects across scenes)
  if (p.subject.identity_notes) {
    parts.push(p.subject.identity_notes);
  }

  // Environment
  parts.push(`Setting: ${p.environment.location}.`);
  if (p.environment.props.length > 0) {
    parts.push(`Props: ${p.environment.props.join(', ')}.`);
  }
  parts.push(`Atmosphere: ${p.environment.atmosphere}.`);
  if (p.environment.time_of_day) {
    parts.push(`Time of day: ${p.environment.time_of_day}.`);
  }

  // Lighting
  parts.push(`Lighting: ${p.lighting.style}.`);
  parts.push(`Color temperature: ${p.lighting.color_temperature}.`);
  if (p.lighting.practical_lights) {
    parts.push(`Practical lights: ${p.lighting.practical_lights}.`);
  }

  // Audio/speech direction
  parts.push(`The speaker says: "${p.audio.speech_text}"`);
  parts.push(`Voice style: ${p.audio.speech_style}.`);
  if (p.audio.ambient_sound) {
    parts.push(`Ambient sound: ${p.audio.ambient_sound}.`);
  }

  // Style
  parts.push(`Visual style: ${p.style.visual_style}, ${p.style.rendering_quality}.`);
  parts.push(`Color palette: ${p.style.color_palette}.`);
  parts.push(`Aesthetic: ${p.style.aesthetic_reference}.`);

  return parts.join(' ');
}

function buildVeoNegativePrompt(scene: VeoScenePrompt): string {
  return scene.negative_prompt;
}
```

### 2.2 Veo API Call Structure

```typescript
// src/services/veo-generation.service.ts

import { VertexAI } from '@google-cloud/vertexai';

async function generateSceneVideo(scene: VeoScenePrompt): Promise<string> {
  const prompt = buildVeoPromptString(scene);
  const negativePrompt = buildVeoNegativePrompt(scene);

  // Vertex AI Veo API call
  const request = {
    model: scene.generation_config.model,
    prompt: prompt,
    negativePrompt: negativePrompt,
    videoConfig: {
      aspectRatio: scene.aspect_ratio,
      durationSeconds: scene.duration_seconds,
    },
    safetySettings: {
      filter: scene.generation_config.safety_filter,
    },
  };

  // The actual API shape depends on the Vertex AI SDK version.
  // Adapt to your current SDK integration.
  const result = await vertexAiClient.generateVideo(request);
  return result.videoUri; // GCS URI of the generated video
}
```

## Part 3: Gemini Scene Structuring Agent

This is the Gemini 2.5 Pro agent that takes the user's normalized ad request and produces an array of Veo scene prompts.

### 3.1 Where It Fits in the Pipeline

```
NormalizedRequest (from AdCreationForm)
  -> Gemini: Creative Brief Generation (existing)
  -> Gemini: Script Generation (existing)
  -> Gemini: Scene Prompt Structuring  <-- THIS AGENT
  -> Output: VeoScenePrompt[] (one per scene)
  -> Veo API: generate video per scene
```

### 3.2 Input to the Agent

The agent receives the **NormalizedRequest** which contains all user inputs:

```typescript
interface NormalizedRequest {
  // Core Configuration (Required)
  prompt: string;
  platform: 'tiktok' | 'instagram_reels' | 'youtube_shorts';
  aspectRatio: '9:16' | '1:1';

  // Product Context
  product: {
    name: string;
    description: string;

  targetAudience?: string;
  cta?: string;
```

### 3.3 Gemini System Prompt

This is the system prompt for the Gemini 2.5 Pro call that structures scene prompts:

```typescript
const SCENE_STRUCTURING_SYSTEM_PROMPT = `You are a video ad scene director for PhanesUGC. Your job is to take a completed ad script and its creative context, and produce a structured JSON array of scene prompts that will be sent to a video generation AI (Veo 3).

## Your Role
You receive:
1. A creative brief with product info, tone, audience, and visual style
2. A completed script with hook, scene-by-scene voiceover lines, and CTA
3. Technical constraints (platform, aspect ratio, total duration, language)

You produce:
An array of scene prompt objects, one per script scene, following the exact schema provided.

## Rules

### Scene Count and Duration
- Each voiceover line in the script becomes exactly one scene
- Scene durations must sum to the total ad duration
- Typical scene durations: 3-8 seconds each
- Hook scene: 2-4 seconds (grab attention fast)
- Body scenes: 4-7 seconds each
- CTA scene: 3-5 seconds

### Visual Storytelling
- Scene 1 (hook) must be visually arresting — movement, contrast, or surprise
- Each subsequent scene should visually escalate or shift perspective
- The CTA scene should feel conclusive — product hero shot or clear visual endpoint
- Vary shot types across scenes — do not repeat the same framing
- Vary camera motion — alternate between static, push-in, pull-out, etc.

### Product Representation
- The product should be visible or referenced in at least 60% of scenes
- Use the product description to write accurate visual descriptions
- If brand colors are available, incorporate them into color_palette
- Never invent product features not present in the input

### People in Scenes
- If the target audience suggests a demographic, cast the scenes accordingly
- When using people, keep identity_notes consistent across scenes where the same person appears
- For UGC/testimonial style: use selfie angles, casual settings, smartphone camera feel
- For product showcase style: use studio lighting, clean compositions

### Audio/Speech
- speech_text must be copied EXACTLY from the script voiceover lines — do not modify
- speech_style should be consistent across all scenes (same voice character)
- Match speech_style to the tone preference:
  - direct -> "clear, confident, measured pace"
  - professional -> "authoritative, polished, steady pace"
  - casual -> "relaxed, conversational, natural pace"
  - enthusiastic -> "energetic, upbeat, slightly faster pace"

### Negative Prompt
- Always include this base: "no text burned into video, no watermark, no logo, no split screen, no collage, no anime, no cartoon, no low resolution, no blurry"
- Add "no distorted faces, no extra limbs, no unnatural skin" for any scene with people
- Add scene-specific exclusions as needed

### Text Overlays
- Only enable text_overlay for hook scenes and CTA scenes by default
- Body scenes should rely on speech + subtitles, not overlays
- Overlay text should be short (3-6 words max)
- Position overlays in top_third to avoid subtitle conflict at bottom

### CTA Scene
- Only the LAST scene should have cta.enabled = true
- Use the user-provided CTA text, or generate one if not provided
- CTA scene should feature the product prominently

### Transitions
- First scene: transition_in = "cut"
- Between scenes: alternate between "cut" and "fade" for pacing variety
- Last scene: transition_out = "fade"

### Platform-Specific Notes
- TikTok: fast pacing, high energy, trend-aware visuals
- Instagram Reels: polished, aspirational, lifestyle-forward
- YouTube Shorts: slightly more informational, can be calmer

## Output Format
Return ONLY a valid JSON array of scene objects. No markdown, no explanation, no wrapping.
Each object must follow the VeoScenePrompt schema exactly.`;
```

### 3.4 Gemini API Call Implementation

```typescript
// src/services/scene-structuring.service.ts

import { GoogleGenerativeAI } from '@google/generative-ai';

@Injectable()
export class SceneStructuringService {
  private genAI: GoogleGenerativeAI;
  private model: any;

  constructor(private configService: ConfigService) {
    this.genAI = new GoogleGenerativeAI(
      this.configService.get('GEMINI_API_KEY'),
    );
    this.model = this.genAI.getGenerativeModel({
      model: 'gemini-2.5-pro',
      generationConfig: {
        responseMimeType: 'application/json',
        temperature: 0.7,
      },
    });
  }

  async structureScenes(
    request: NormalizedRequest,
  ): Promise<VeoScenePrompt[]> {
    const userPrompt = this.buildUserPrompt(request);

    const result = await this.model.generateContent({
      systemInstruction: SCENE_STRUCTURING_SYSTEM_PROMPT,
      contents: [{ role: 'user', parts: [{ text: userPrompt }] }],
    });

    const responseText = result.response.text();
    const scenes: VeoScenePrompt[] = JSON.parse(responseText);

    // Validate and enrich
    return this.validateAndEnrich(scenes, request);
  }

  private buildUserPrompt(request: NormalizedRequest): string {
    return `Generate scene prompts for this ad:

## Technical Constraints
- Platform: ${request.platform}
- Aspect Ratio: ${request.aspectRatio}
- Total Duration: ${request.durationSec} seconds
- Language: ${request.language}

## Product
- Name: ${request.product.name}
- Description: ${request.product.description}
- Benefits: ${request.product.benefits.join(', ')}
${request.product.pricing ? `- Pricing: ${request.product.pricing}` : ''}
${request.product.specialOffers ? `- Special Offer: ${request.product.specialOffers}` : ''}
${request.product.scrapedData?.brandColors ? `- Brand Colors: ${request.product.scrapedData.brandColors.join(', ')}` : ''}
${request.product.scrapedData?.tagline ? `- Tagline: ${request.product.scrapedData.tagline}` : ''}

## Creative Direction
- Tone: ${request.tone}
- Visual Style: ${request.visualStyle}
- Target Audience: ${request.targetAudience || 'general'}
- CTA: ${request.cta || 'not specified — generate one'}

## Script
Title: ${request.script.title}
Hook: ${request.script.hook}

Voiceover Lines:
${request.script.voiceoverLines.map((l) => `Scene ${l.scene}: "${l.text}"`).join('\n')}

CTA Line: "${request.script.cta}"

## Overrides
- Background music: ${request.enableBackgroundMusic ? 'yes' : 'disabled by user'}
- CTA overlay: ${request.enableCtaOverlay ? 'yes' : 'disabled by user'}

## Output
Generate exactly ${request.script.voiceoverLines.length} scene prompt objects.
Scene durations must sum to exactly ${request.durationSec} seconds.
Return a JSON array only.`;
  }

  private validateAndEnrich(
    scenes: VeoScenePrompt[],
    request: NormalizedRequest,
  ): VeoScenePrompt[] {
    // Ensure durations sum correctly
    const totalDuration = scenes.reduce((sum, s) => sum + s.duration_seconds, 0);
    if (totalDuration !== request.durationSec) {
      // Adjust last scene to compensate
      const diff = request.durationSec - totalDuration;
      scenes[scenes.length - 1].duration_seconds += diff;
    }

    // Ensure speech_text matches script exactly
    for (const scene of scenes) {
      const scriptLine = request.script.voiceoverLines.find(
        (l) => l.scene === scene.scene_id,
      );
      if (scriptLine) {
        scene.prompt.audio.speech_text = scriptLine.text;
      }
    }

    // Ensure only last scene has CTA enabled
    scenes.forEach((s, i) => {
      s.prompt.cta.enabled = i === scenes.length - 1 && request.enableCtaOverlay;
      if (s.prompt.cta.enabled && !s.prompt.cta.text) {
        s.prompt.cta.text = request.cta || 'Get Started';
      }
    });

    // Set project_id placeholder (will be filled by pipeline)
    scenes.forEach((s) => {
      s.generation_config = {
        model: 'veo-3.1',
        seed: null,
        safety_filter: 'standard',
        retry_count: 0,
        priority: 'normal',
      };
    });

    // Ensure base negative prompt is present
    const baseNeg = 'no text burned into video, no watermark, no logo, no split screen, no collage, no anime, no cartoon, no low resolution, no blurry';
    scenes.forEach((s) => {
      if (!s.negative_prompt || !s.negative_prompt.includes(baseNeg)) {
        s.negative_prompt = baseNeg + (s.negative_prompt ? ', ' + s.negative_prompt : '');
      }
    });

    return scenes;
  }
}
```

```typescript
// src/services/scene-persistence.service.ts

async function persistScenes(
  bizId: string,
  projectId: string,
  scenes: VeoScenePrompt[],
): Promise<void> {
  const batch = firestore.batch();
  const scenesRef = firestore
    .collection('businesses').doc(bizId)
    .collection('projects').doc(projectId)
    .collection('scenes');

  for (const scene of scenes) {
    const docRef = scenesRef.doc();
    batch.set(docRef, {
      id: docRef.id,
      projectId,
      sceneOrder: scene.scene_id,
      durationSec: scene.duration_seconds,
      visualType: 'ai_video',
      visualPrompt: buildVeoPromptString(scene),
      cameraMotion: scene.prompt.shot.camera_motion,
      overlayText: scene.prompt.text_overlay.enabled
        ? scene.prompt.text_overlay.text
        : null,
      transitionIn: scene.transition_in,
      transitionOut: scene.transition_out,
      assetStorageKey: null,
      assetType: 'video',
      generationStatus: 'pending',
      generationError: null,
      // Store the full structured prompt for regeneration
      structuredPrompt: scene.prompt,
      negativePrompt: scene.negative_prompt,
      generationConfig: scene.generation_config,
      createdAt: FieldValue.serverTimestamp(),
      updatedAt: FieldValue.serverTimestamp(),
    });
  }

  await batch.commit();

  // Update project stage
  const projectRef = firestore
    .collection('businesses').doc(bizId)
    .collection('projects').doc(projectId);
  await projectRef.update({
    'stages.scenes': 'done',
    updatedAt: FieldValue.serverTimestamp(),
  });
}
```

### 4.3 Schema Extension

The current Firestore scene schema from `firestore_schema.md` does not include `structuredPrompt`, `negativePrompt`, or `generationConfig`. These should be added:

| Field | Type | Required | Description |
|---|---|---|---|
| `structuredPrompt` | `map` | no | Full structured prompt object for regeneration |
| `negativePrompt` | `string` | no | Negative prompt sent to Veo |
| `generationConfig` | `map` | no | Model, seed, safety, retry count |

This allows scene regeneration to re-use or modify the structured prompt without re-running Gemini.

### 5.3 Scene Regeneration

When a user regenerates a single scene:

```typescript
async function regenerateScene(
  bizId: string,
  projectId: string,
  sceneId: string,
  modifiedPrompt?: Partial<VeoScenePrompt['prompt']>,
): Promise<void> {
  const sceneDoc = await getSceneDoc(bizId, projectId, sceneId);
  let structuredPrompt = sceneDoc.structuredPrompt;

  // Apply user modifications if provided
  if (modifiedPrompt) {
    structuredPrompt = { ...structuredPrompt, ...modifiedPrompt };
  }

  // Rebuild full scene object
  const scene: VeoScenePrompt = {
    scene_id: sceneDoc.sceneOrder,
    project_id: projectId,
    duration_seconds: sceneDoc.durationSec,
    aspect_ratio: sceneDoc.aspectRatio || '9:16',
    prompt: structuredPrompt,
    transition_in: sceneDoc.transitionIn,
    transition_out: sceneDoc.transitionOut,
    negative_prompt: sceneDoc.negativePrompt,
    generation_config: {
      ...sceneDoc.generationConfig,
      retry_count: sceneDoc.generationConfig.retry_count + 1,
    },
  };

  // Regenerate via Veo
  await updateSceneStatus(sceneId, 'generating');
  const videoUri = await generateSceneVideo(scene);
  const gcsPath = await moveToProjectPath(videoUri, bizId, projectId, sceneId);

  await updateScene(sceneId, {
    assetStorageKey: gcsPath,
    generationStatus: 'completed',
    structuredPrompt: scene.prompt,
    generationConfig: scene.generation_config,
  });

  // Re-trigger subtitle pipeline for the full project
  // (because audio changed, subtitles need regeneration)
  await triggerSubtitleRegeneration(bizId, projectId);
}
```

## Summary of Key Decisions

| Decision | Choice | Reason |
|---|---|---|
| Prompt format | Structured JSON -> serialized to text | Allows regeneration with modifications without re-running Gemini |
| Scene structuring model | Gemini 2.5 Pro | Already configured in the project, strong JSON output |
| Output format | responseMimeType: application/json | Forces Gemini to return valid JSON, no parsing issues |
| Speech text | Copied verbatim from script | Must match exactly for subtitle alignment downstream |
| Text overlays | Rendered by Remotion, not Veo | Controllable typography, font consistency, safe area compliance |
| Negative prompt | Base set hardcoded + Gemini additions | Prevents common Veo artifacts (burned text, watermarks) |
| Full prompt stored in Firestore | structuredPrompt field on scene doc | Enables scene regeneration without re-running the full pipeline |
| Voice consistency | Same speech_style across all scenes | Prevents jarring voice changes between scenes |
